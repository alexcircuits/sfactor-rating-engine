# Рейтинговый движок SFactor

Go-сервис, который рассчитывает рейтинг финансового здоровья на основе кредитного отчёта УБКІ (XML-шаблон 10) и возвращает оценку от 0 до 100 состоящую из девяти оцениваемых показателей, пояснения на украинском языке и дополнительную информацию из кредитной истории.

Движок может работать как HTTP-сервис или как инструмент командной строки. Он использует только стандартную библиотеку Go и не имеет сторонних зависимостей.

## Начало работы

Требуется Go 1.26.6 или новее. Выполните следующие команды из корневой директории репозитория:

```bash
git clone https://github.com/alexcircuits/sfactor-rating-engine.git
cd sfactor-rating-engine
go test ./...
go run ./cmd/score -table rating/testdata/report3.xml
```

По умолчанию CLI выводит результат в формате JSON. Используйте `-table` для human-friendly сводки, `-income` для указания подтверждённого ежемесячного дохода в гривнах и `-as-of` для задания расчётной даты:

```bash
go run ./cmd/score -income 25000 -as-of 2026-07-08 report.xml
```

## HTTP API

Запуск сервера:

```bash
go run ./cmd/server -port 8080
```

### Расчёт рейтинга

`POST /rating` принимает multipart-форму с ограничением общего размера запроса в 4 МиБ.

| Поле | Обязательное | Описание |
| --- | --- | --- |
| `report` | Да | XML-отчёт УБКІ, шаблон 10 |
| `monthly_income` | Нет | Подтверждённый ежемесячный доход в гривнах, например `25000.50` |
| `as_of` | Нет | Расчётная дата в формате `YYYY-MM-DD` |

```bash
curl --fail-with-body \
  -F report=@rating/testdata/report3.xml \
  -F monthly_income=24000 \
  -F as_of=2026-07-08 \
  http://localhost:8080/rating
```

При успешном запросе рейтинг возвращается в формате JSON. Ответ включает `score`, `raw`, `band`, `parameters`, а также применённые ограничения и флаги, если они есть. Если подходящие кредитные сделки отсутствуют, возвращается `available: false` с `reason: "no_credit_history"`.

Если доход не указан или равен нулю, движок использует последний положительный задекларированный доход из отчёта, если его возраст не превышает 12 месяцев. В противном случае долговая нагрузка остаётся неизмеренной.

По умолчанию в качестве расчётной даты используется дата формирования отчёта, а если она отсутствует — текущая дата. Дата, предшествующая дате формирования отчёта, не принимается.

Ошибки имеют следующий формат: `{"error": "code", "message": "description"}`.

| Статус | Код ошибки | Причина |
| --- | --- | --- |
| 400 | `invalid_request` | Некорректные, неизвестные или повторяющиеся поля; повреждённый multipart-запрос; некорректный доход или дата |
| 400 | `missing_report` | Отчёт отсутствует или пуст |
| 400 | `invalid_report` | Некорректный XML УБКІ |
| 405 | `method_not_allowed` | Неподдерживаемый HTTP-метод |
| 413 | `report_too_large` | Размер запроса превышает 4 МиБ |
| 415 | `unsupported_media_type` | Запрос не использует `multipart/form-data` |

Все ответы содержат заголовок `Cache-Control: no-store`. Ответы с ошибками не содержат данные кредитного отчёта.

Полный контракт API находится в [api/openapi.yaml](api/openapi.yaml), а Go-типы ответов — в [rating/result.go](rating/result.go).

## Как работает расчёт рейтинга

Каждый показатель имеет собственную кривую оценки, вес и диапазоны значений. Кривые интерполируют значения между настроенными точками, а диапазоны определяют, является ли измеренное значение хорошим, средним или плохим.

| Показатель | Вес |
| --- | ---: |
| Возраст кредитной истории | 8% |
| Дни без просрочек | 18% |
| Текущие просроченные кредиты | 15% |
| Текущая сумма просроченной задолженности | 12% |
| Активные кредиты | 10% |
| Погашенные кредиты | 7% |
| Новые кредиты за недавний период | 8% |
| Ежемесячные платежи как процент от дохода | 12% |
| Кредитные заявки за недавний период | 10% |

Показатели, которые невозможно измерить, помечаются как `unknown`. Их веса исключаются из расчёта, а оставшиеся веса нормализуются.

`raw` представляет собой сумму вкладов всех показателей. Итоговый рейтинг округляется до целого числа и при необходимости ограничивается установленным максимальным значением.

Оценки распределяются следующим образом:

- 0–45 — низкий рейтинг;
- 46–74 — средний рейтинг;
- 75–100 — высокий рейтинг.

Период для недавних событий по умолчанию составляет 183 дня. Периоды для терминальной задолженности и возраста данных о доходах рассчитываются в календарных месяцах.

Денежные значения хранятся в целых копейках, чтобы обеспечить точное сравнение с пороговыми значениями.

Поручительства исключаются из расчёта. Проданные и списанные долги считаются активными, а не погашенными.

Кредитные карты с положительным кредитным лимитом также считаются активными, если только их последний статус не указывает на продажу или списание задолженности.

Небольшие остаточные просрочки в размере 10 грн или меньше игнорируются.

Ограничения рейтинга по умолчанию:

| Причина | Условие | Максимальный рейтинг |
| --- | --- | ---: |
| `current_overdue` | Общая учитываемая просроченная задолженность не менее 100 грн | 45 |
| `terminal_debt` | Зафиксированная продажа или списание долга в течение последних 36 месяцев | 45 |
| `terminal_debt_aged` | Более старая неурегулированная терминальная задолженность в пределах 72 месяцев | 74 |

Ограничения проверяются именно в указанном порядке и применяются только в том случае, если они уменьшают итоговый рейтинг.

Терминальные события без указанной даты считаются недавними.

Терминальные задолженности считаются текущей просроченной задолженностью в течение 36-месячного периода, даже если их сумма никогда не была указана.

Флаги (`write_off`, `sold`, `enforcement`, `mfo_pressure`), распределение по кредиторам и подписки на мониторинг предоставляют дополнительный контекст, но не влияют на итоговую оценку.

Веса, пороговые значения и временные периоды определены в [rating/config.go](rating/config.go) и [rating/indicators.go](rating/indicators.go).

## Структура проекта

```text
ubki/              Парсинг XML, типы отчётов и коды бюро
rating/            Измерения, кривые оценки, ограничения и типы ответов
internal/httpapi/  HTTP-обработчики и валидация запросов
cmd/score/         Инструмент командной строки
cmd/server/        HTTP-сервер
api/               Схема OpenAPI
docs/              Спецификации модели и заметки по реализации
```

Основной процесс расчёта начинается в [rating/rate.go](rating/rate.go).

## Разработка

```bash
go test ./...
go test -race ./...
go vet ./...
go build ./...
```

Тесты включают синтетические сценарии, пять реальных тестовых кредитных отчётов и один синтетический отчёт в `rating/testdata/`.

Ожидаемые JSON-ответы хранятся в `rating/testdata/golden/`.

После намеренного изменения алгоритма расчёта необходимо пересоздать эти файлы и проверить различия:

```bash
go test ./rating -update
```

## Развёртывание

```bash
docker build -t sfactor-rating-engine .
docker run --rm -p 8080:8080 sfactor-rating-engine
```

Docker-образ запускает статически собранный бинарный файл от имени непривилегированного пользователя.

После получения `SIGINT` или `SIGTERM` сервер предоставляет активным запросам до 30 секунд для завершения.

Рекомендуется развёртывать сервис за API-шлюзом, который выполняет аутентификацию клиентов и ограничивает частоту запросов, поскольку сам сервис не реализует ни одну из этих функций.

Для прямого доступа из браузера передайте:

`-cors-origin https://your-app.example`

чтобы разрешить запросы с указанного origin.

По умолчанию CORS-заголовки не добавляются.

Рейтинг предназначен для финансового образования. Текущая модель не была откалибрована на основе фактических результатов погашения кредитов и не выполняет проверки, необходимые для принятия решения о кредитовании.
